## チェックと更新のルール

`- [x]` はそのタスクの完了条件を満たした状態、`- [ ]` は残作業がある状態とする。着手中はチェックを外したまま、タスク本文に「着手中」と残作業を書く。

実装と必要な検証を終えたら、**同じ作業で必ず該当タスクを `- [x]` に更新する**。実装ファイル・テスト・結果の参照を残し、上の完了件数と現在地も更新する。タスクを追加・分割した場合も件数を直す。不具合で完了条件を満たさなくなったタスクは、理由を添えてチェックを戻す。

M0は「動く初版」の完了を表す。仕様への適合を調べるM1、LLMの行動を確認するM3、最終判定のM5は、それぞれ独立してチェックする。テスト名に受け入れケースのIDが含まれることや、テスト件数だけで網羅済みとは判定しない。

生ログはリポジトリへ蓄積せず、固定名の `/tmp/agent-logs/<プロジェクト>/` またはCIのログへ出す。管理票や受け入れ結果には、コマンド・対象版・実行環境・結果・ログ参照を要約して残す。検証を伴わない計画や文言修正では、実装タスクにチェックを入れない。

## テストの進め方

コアの型・版・状態・検索・保存・再試行は、既存のPython自動テストで検証する。LLMを含む利用・連携の検証は、実装が整ってから **`claude -p --safe-mode`** で実施する。LLMのAPIを直接呼ぶ実装やSDKで、この受け入れを代替しない。

ローカルの `claude --help` で `-p` と `--safe-mode` の対応を確認済み。safe-modeではCLAUDE.md、カスタムSkill、MCP等が無効になるため、**Guideの場所・LATIS CLI・DB・作業ディレクトリを毎回プロンプトに明示する**。safe-modeでも通常の権限処理は有効なので、テスト基盤で実際に必要な操作ができるか確認する。

Pythonによる既定シナリオの成功と、Claudeが自分で探索・照合・判断することを区別して記録する。正常な検索0件、CLIの失敗、権限不足、LLMの不応答も区別する。

## M6 次期仕様への拡張

M5後の拡張候補を管理する。ここでの完了は、調査・採否判断・採用範囲の仕様化までを指す。採用した機能には、版付きのSpec/API、互換性・移行方針、受け入れ条件を定め、追加の実装マイルストーンとチェック付きタスクを作る。保留・不採用の場合も理由を残す。

根拠は [設計判断](v0.3.0/LATIS_Design_Decisions.md) とSpec §8.4・§12〜13。以下の候補は現行仕様44タスクの完了件数には含めない。

- [ ] **M6-01 20万合意と開発効率の評価を設計する。** 本文長、関係・Scope・履歴量、更新頻度を定義し、時間・メモリ・構築更新費用を測る。同じLLMと課題でMarkdown中心の作業とも比較し、改善目標を定める。
- [ ] **M6-02 大規模索引と変更検知の最適化を判断する。** FTS・n-gram等の検索索引とScope epoch等を評価する。全走査と同じ一致条件・順序・診断・変更検知を保つ受け入れ条件を定める。
- [ ] **M6-03 推論検索の追加を判断する。** 語句・関係探索、DecisionRAG等、併用を比較する。正本と派生索引、索引版とDB版、候補と根拠、索引更新遅れ、専用ページング、失敗時の経路を仕様化する。LLMを使う評価はClaude CLIで行う。
- [ ] **M6-04 旧形式の移行を仕様化する。** 実際の旧データを基に、旧値・原文・来歴・未確認状態を保存する変換規則と検証を定める。採択・確認・主体の情報を推測で補わない。
- [ ] **M6-05 Markdown importを判断する。** 編集元版、変更意図、出所、冪等性、メタデータと関係の変更範囲、採択経路を定義する。現在の読み取り専用投影と区別する。
- [ ] **M6-06 検証状態の集約と利用インターフェースを判断する。** drift集約、HTTP、MCP、グラフUI等の必要性を実利用から評価する。採用する入口と操作契約を限定し、コアの保存・照合と分離する。
- [ ] **M6-07 主体と権限を仕様化する。** party、本人性、委任、複数当事者の同意・不同意・撤回、読み取り・更新権限を定義する。既存の自己申告を検証済みの権限や同意へ読み替えない。
- [ ] **M6-08 優先規則と時間評価を判断する。** 適用条件、例外、優先・継承の可否、有効時刻と記録時刻、過去時点の評価を定義する。採用する規則と未対応時の扱いを明示する。
- [ ] **M6-09 拡張語彙を仕様化する。** 名前空間、追加データ、根拠版、解釈できない意味の扱いを定める。未知の関係を内容非依存と推測せず、情報を保持する。
- [ ] **M6-10 消去とredactionを仕様化する。** 本文の可用性、過去版の同一性、再検証不能、退避・複製先への影響を定義する。
- [ ] **M6-11 digestと署名を判断する。** ハッシュ対象、正規化、署名主体、外部チェックポイント、消去後の検証範囲を定義する。外部artifactのハッシュとLATIS内の記録IDを区別する。
- [ ] **M6-12 複数作業場所と分散同期を仕様化する。** リポジトリ・ブランチ・作業コピーの文脈、競合、履歴、同一DBの分岐、マージを定義する。Git上の参照とLATIS自体の同期を分ける。
