# LATIS / Agreement Explorer — 展示UIデザイン指針

**版:** v2.0（2026-11-06 JST）\
**用途:** 2026-11-07 展示用ビューアの実装指示。LATIS Core / API の規範仕様ではない。\
**関連:** `LATIS_Graph_UI_Implementation_Plan_v2_2026-11-06.md`、`LATIS_Graph_UI_Demo_Scenario_v2_2026-11-06.md`\
**参考:** 添付 `LATIS_Graph_Pulse_Design_2026-11-06.pdf`（とくに p.2 待機、p.3 追加、p.4 改訂、p.5 ビジュアル言語）。**PDFの再現・トレースは目的ではない。**

## 1. デザインの狙い

> **整然と並ぶ合意の階層が、人とAIの判断を記録し、変更された箇所だけが静かに動く。**

キーワードは **質実剛健 / 柔軟 / 先進性 / わずかに前衛 / System 7を大胆に現代化**。昔のOSの素朴さをそのまま模写するのではなく、明快な境界線・反転選択・情報密度・道具らしさを現代の画面で再構成する。

- **第一印象:** 「整理された、信頼できそうな道具」。黒背景のSF風、ネオン、星屑、常時脈動、巨大なレーダー装飾をやめる。
- **第二印象:** 「複数の合意が階層と関係で繋がっている」。蜘蛛の巣の自由配置でなく、固定列・行・インデントで示す。
- **第三印象:** 「確定した変更が分かる」。追加は行が増え、改訂は同じIDの行が反転して差分が出る。出所と旧版へ戻れる。
- **長く使える表現:** 1bit風の線・形・余白を基調にし、演出がなくても内容を読める。

正式な画面名は **`LATIS / Agreement Explorer`**。日本語見出しは **「合意エクスプローラー」**。以前の仮称 `GRAPH PULSE` は画面タイトル・サービス名・ファイル名・機能名として使わない。更新時の短い強調を「反転」「確定通知」と記述する。

## 2. 画面の情報構造：固定3列とインスペクタ

PDF p.2〜4の「Scope｜Agreement｜Rationale/Question/Source」を発展させ、**行方向を揃えた階層ブラウザ**とする。あくまでも**階層は `contains` によるScope間の明示関係**で、`scoped_to` は所属、`supports` などは横断的な関連である。理由が画面上で合意の右側に並ぶことを、機械的な親子関係と解釈しない。

```text
┌─ LATIS / Agreement Explorer ── Project: demo-logs ── [LIVE] rev 00040 ┐
│                                                                         │
│  合意エクスプローラー / Explorer                           Filter [____] │
│  ┌── Scope / 範囲 ─────┬── Agreement / 合意 ─────┬── Context / 理由等 ┐ │
│  │ ▾ ログ管理          │ 個人情報を出力しない     │ —                  │ │
│  │   ├ 通常ログ        │ ◎ 保持期間 24時間       │ ─ 保存容量のため   │ │
│  │   │                 │ ◎ タイムスタンプ（追加）│ ─ 時差を防ぐため   │ │
│  │   ├ 監査ログ        │ ◎ 保持期間 90日         │ ─ 監査に備える     │ │
│  │   └ 障害対応        │ ◎ trace_idで突き合わせ │ · 振り返りメモ    │ │
│  └───────────────────┴───────────────────────┴─────────────────────┘ │
│  選択中: 通常ログの保持期間      ID: ag_log_retention   rev_ag_3        │
│  ┌─ Inspector / 詳細 ───────────────────────────────────────────────┐  │
│  │ 本文: 通常ログを24時間保持する。  根拠: 保存容量とコストを抑えるため│  │
│  │ 所属: 通常ログ   履歴: rev_ag_3 / rev_ag_2   出所: …               │  │
│  └─────────────────────────────────────────────────────────────────┘  │
│  CHANGE LOG  00040 LOAD — 初期表示 / 実apply時のみ NEW・REVISED を表示 │
└─────────────────────────────────────────────────────────────────────────┘
```

> この図は**情報構成の概念図**。実画面ではInspectorは原則右の縦ペイン、Change Logは下部に配置する。3列はメインキャンバス内で維持する。

### 2.1 優先する順序

1. 画面上段: `LATIS`、画面名、表示対象のproject、`LIVE/REPLAY/RECORDED`、`graph_revision`。巨大な見せ物風タイトルは不要。
2. メイン: **Scope → Agreement → Context**の整列した3列（中心の最大領域）。Scopeは展開/折り畳みできる。見えている合意へ線で接続する場合も短い直交線に限定する。
3. 右Inspector: 選択ノードの**現在本文・ID・revision・所属・理由・来歴**。説明を読み上げられる文字サイズ。
4. 下部: **確定済みの変更履歴**を新しい順に2〜4件。任意で更新した範囲の小さなbefore/after。
5. その他: ツールバー/フィルターは小さく。初期表示で列やパネルが乱立しない。

### 2.2 行の規則

- Scopeの階層表示は`contains`の**active/confirmed**な関係から作る。**親Scopeの合意が子Scopeへ自動適用されるとは表示しない**。
- 合意の所属は`scoped_to`のactive/confirmedから求める。複数所属の場合、同じstable IDを別の合意として増殖させず、表示上の参照/所属数で示す。
- Context列は、当該合意に**実際の関係で結ばれた**`rationale / intent / question / artifact`のみを表示。「理由があるはず」と推測して作らない。
- 候補・未確定は破線と「候補」表記。採択済みとは形と文字で区別し、色のみで区別しない。
- 同一行の改訂では**IDと位置を保持**。表示が増えるときは該当Scopeの予約位置へ挿入し、無関係な既存行を大きく動かさない。
- 件数が増えたらScopeの折り畳み・スクロールで解決。すべての関係線を描かない。クリックした対象の関係だけ詳細へ表示する。

## 3. 視覚言語

| 項目 | 標準 | 理由 |
|---|---|---|
| 背景 | `#F2F1ED` または `#F7F7F4` | あたたかみを少し持つ紙色。真っ白な広面積を避ける。 |
| 文字・強調線 | `#111111` | 高コントラストで道具らしい。 |
| 補助文字 | `#555555` | ID、日時、説明。 |
| グリッド・区切り | `#C9C9C3`〜`#D9D9D5` | 小さな点格子、1px罫線。装飾として全面へ強く敷かない。 |
| 選択状態 | **白黒反転**、左の小さなマーカー | カラーに依存せず、System 7的な操作性。 |
| 確定通知のアクセント | 任意：単色 `#FF4A1C`、2〜3秒だけ | PDF p.3〜5の思想を残す。ただし1bitだけでも成立する。 |
| 未確定 | 破線・白抜き記号・明示ラベル | 「未確定」を色で表さない。 |
| 退役・置換 | 斜線や文字ラベル | 削除されたかのように消さない。 |

**アクセントの運用:** 常時オレンジのUIにしない。アクセントは**実際の`apply`で確定した変更**を通知する短時間の信号だけ。`save-draft`でも`graph_revision`は進むため、**revision増加だけで色を点けない**。対象commitの来歴/操作を確かめる。動作不安定なら**反転のみ**でよい。

### 3.1 字体

- タイトルと本文: システム日本語サンセリフで十分。例として**IBM Plex Sans JP**を採用可能。
- ID・数値・日時: 等幅系。例として**IBM Plex Mono**。
- 1bit的な見出しの限定的な使用: **DotGothic16**。大きなコピーに多用しない。
- 外部CDN不要、実機で読み込み済みのフォントかライセンス確認済みの自己ホスト方式。フォントが入らなくても見た目を維持するfallbackを設定する。
- 推奨基準: 1920×1080で合意タイトル18〜22px、本文20〜26px、見出し14〜16px、ID/注釈12〜14px。数字が小さく潰れるなら注釈を減らす。実機視認性を最優先。

### 3.2 操作要素

- 正方形に近いボタン、はっきりした罫線、シンプルな開閉三角、行頭の小記号。
- ウィンドウ風のヘッダ線・ディザ影は**最小限**。過剰な縞・角飾り・HUDメーターは不要。
- 高度なドラッグ配置は不要。Scopeの展開、項目選択、検索語フィルター、履歴の選択に集中する。
- 追加・変更の小さなマーカー`NEW` / `REVISED`、日付・版は目で追える。

## 4. モーション：何が変わったか、約3秒で分かる

| 契機 | 表示 | 避けること |
|---|---|---|
| 初回ロード / 再接続 / DB切替 | **静的**に現在状態へ同期し、LIVE/RESETを明示 | 古い変更を新規に見せる演出 |
| `consult` / `save-draft` | 必要なら「検討中」を文字で表示。採択済み合意に確定演出なし | まだ確定していない対象への確定色 |
| `apply`で合意を新規採択 | 対象Scopeの行へ`NEW`、短い反転/ディザ出現、関連する**実在の**理由へ短い線を描く | 画面全体の点滅、理由の捏造 |
| `apply`で既存合意を改訂 | **同じID・同じ行**で反転、Inspectorに`24時間 → 48時間`、短い確定色 | 新しい合意として増やすこと、全体の並べ替え |
| 同じcommit内で複数変更 | commitを1件として扱い、変更対象だけ順に数段階強調 | データにない中間状態を作る |
| 通知が重なった | 次の通知をキューへ、または差分件数だけ表示 | 眩しい重畳エフェクト |

切り替えに`steps(2〜4)`、消え際に短い`ease-out`を使える。**常時アニメーションなし**。約2秒以上の激しい反転やストロボ、リングの多重波紋は不要。`prefers-reduced-motion`と「動きを減らす」設定に対応し、最小表示では単なる行背景反転と文字差分だけにする。

## 5. 画面モードと誠実な表示

- **LIVE:** 実在する展示DBをローカルサーバーから読み取り中。接続確認/表示した`graph_revision`を併記。
- **REPLAY:** 実在したcommitを、過去の状態として再表示。常時`REPLAY / ライブではありません`。演出自体を再生してもよい。
- **RECORDED:** 録画。映像内と説明に`RECORDED / 収録映像`を表示。
- **DISCONNECTED:** 最後に検証できた状態を保持し、再接続中と時刻を表示。LIVEのまま最新を装わない。

表示する件数・値・ID・時刻は正本DBから読む。グラフに存在しない`coherence=0.92`等の装飾的な数値や偽の更新日時を置かない。PDF内の数値・ラベルは、あくまで画面例である。

## 6. レイアウトのレスポンシブ優先

- **想定:** 外部ディスプレイの1920×1080、拡張画面、ブラウザー全画面。実モニターの仕様は未確認。
- 1600px以上ではメインの3列と右Inspectorを並列。画面幅が足りない場合はContext列をInspectorへ集約し、Scope+Agreement+Inspectorを残す。
- 1366×768程度では下部の履歴領域を細くし、UIのヘッダー/装飾領域を最小にする。文字を単純に縮小しない。
- 画面から離れた来場者に見せるときは**選択合意の本文と変更差分**を最も大きくする。縦書きスローガンは任意で、採用する場合でもメイン領域を圧迫しない。
- レイアウトは自動生成グラフではなく、固定列・インデント・直交線を基本とする。SVGを使う場合も**部分的なつながり**だけに使う。

## 7. 必須の表示品質チェック

- [ ] 開いた瞬間に、Scopeの親子と「通常ログ／監査ログ」の並列が理解できる。
- [ ] 通常ログ24時間と監査ログ90日が、別のID・別の合意として読める。
- [ ] 1回の新規採択で、**どのScopeに何が増えたか**がひと目で分かる。
- [ ] 1回の改訂で、**同じ合意がどう変わったか**が本文の大きな差分で分かる。
- [ ] 重要な情報が画面外・極小文字・浮遊線の密集に埋まらない。
- [ ] 初期ロード、候補、確定変更、再生、切断を誤認させない。
- [ ] 色を切っても、印刷しても、状態と変化の区別がつく。
- [ ] 1bit演出をすべて無効化しても、使える情報表示として成立する。

## 8. 参考PDFから継承するもの・採らないもの

| 継承する | そのままは採らない |
|---|---|
| p.2の固定3列、Scopeごとの行割り、右Inspector | p.2の大きな縦書き看板と密な微小ラベルを必須とすること |
| p.3の新規合意と理由の同時可視化 | 大きな発光・波紋・全画面の動き |
| p.4の**同じIDで改訂**、大きな前後差分、監査ログ変更なし | 旧版の理由を自動で失効扱いすること |
| p.5の白黒・反転・ディザ・shape/line・表示モードの区別 | `GRAPH PULSE`というタイトル／1bitの再現にこだわって判読性を下げること |

**このUIは展示用の可視化クライアントであり、LATIS自体が新しい合意意味論や自動優先規則を導入するものではない。**
